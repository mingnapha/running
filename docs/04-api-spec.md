## สรุปแบบภาษาธรรมดา

**API คืออะไร** — หน้าเว็บ (ที่พนักงานเห็นบนมือถือ) ไม่ได้คุยกับฐานข้อมูลตรงๆ แต่ส่ง "คำขอ" ไปที่ช่องทางที่กำหนดไว้ เช่น
"ขอตารางคะแนน", "บันทึกการวิ่งนี้", "อนุมัติรายการนี้" — ระบบหลังบ้านจะตรวจว่า **คนนี้มีสิทธิ์ทำไหม** ก่อนทำให้เสมอ

**มีทั้งหมด 56 ช่องทาง** แบ่งตามหน้าที่:

| กลุ่ม | ใช้ทำอะไร | ใครใช้ |
|---|---|---|
| ล็อกอิน | เข้า/ออกระบบ, เปลี่ยนรหัสผ่าน | ทุกคน |
| ข้อมูลของฉัน | ดู/แก้ชื่อที่แสดง, ภาษา, ยอมรับประกาศความเป็นส่วนตัว, ขอลบข้อมูล | ทุกคน |
| ฤดูกาล / ตารางคะแนน | ดูตารางคะแนน, แถบความเคลื่อนไหว, สถิติของฉัน | ทุกคน |
| การวิ่ง | อัปโหลดรูป, บันทึกการวิ่ง, ดูประวัติ, ยกเลิกรายการที่รอตรวจ | พนักงานที่มีสิทธิ์เล่น |
| ตรวจสอบ | ดูคิว, อนุมัติ/ปฏิเสธ (ทีละรายการหรือหลายรายการ), เพิกถอน | ผู้ตรวจ, แอดมิน |
| แอดมิน | ฤดูกาล, กติกา, ผู้มีสิทธิ์, ผู้ใช้, แผนก, ปรับคะแนน, รายงาน CSV, บันทึกตรวจสอบ, ตั้งค่า | แอดมิน |

**ด่านบังคับก่อนใช้งาน** — ล็อกอินครั้งแรกต้อง (1) เปลี่ยนรหัสผ่าน และ (2) กดยอมรับประกาศความเป็นส่วนตัว ก่อนจึงจะใช้ส่วนอื่นได้

**ข้อความแจ้งเตือน 2 ภาษา** — เมื่อทำไม่ได้ ระบบตอบเป็น "รหัส" (เช่น `RUN_DATE_TOO_OLD`) พร้อมข้อความภาษาไทยหรืออังกฤษตามที่ผู้ใช้ตั้งไว้ เช่น "บันทึกย้อนหลังได้ไม่เกิน 7 วัน"

## การออกแบบที่สำคัญ (สำหรับนักพัฒนา)

### ตารางคะแนนแบบ "เกือบ real-time" ที่ไม่มีค่าใช้จ่าย
```
หน้าเว็บ ──ทุก 10 วิ (ขณะเปิดแท็บ)──▶ GET /leaderboard/version   (Worker cache 5 วิ)
         ◀── {version: 18}
ถ้า version เปลี่ยน ──▶ GET /leaderboard?v=18                       (Worker cache ตามเวอร์ชัน)
         ◀── ตารางทั้งหมด → เทียบกับของเดิม → เล่นแอนิเมชัน
(เสริม) Supabase Realtime ping "version 18" → ข้ามการรอ 10 วิ
```
- ตรวจ session ก่อนอ่าน cache ทุกครั้ง — cache ใช้แค่ลดการถามฐานข้อมูล ไม่ข้ามการตรวจสิทธิ์
- response ตารางคะแนนเหมือนกันทุกคน (ไม่มีฟิลด์ "isMe") จึง cache ร่วมกันได้ หน้าเว็บหาแถวตัวเองจาก `userId`

### อัปโหลดรูปผ่าน Worker → R2
1. มือถือบีบอัดเป็น WebP ≤ 1600px และลบ EXIF (GPS) → `POST /uploads/evidence`
2. Worker ตรวจชนิด/ขนาด คำนวณ SHA-256 เก็บที่ `evidence/{profileId}/{uuid}.webp` → คืน `objectKey`
3. `POST /runs` พร้อม `evidenceKeys` → server ตรวจว่าไฟล์มีจริงและอยู่ในโฟลเดอร์ของผู้ใช้ → เรียก `submit_run()`
4. ไฟล์ที่อัปโหลดแต่ไม่ถูกใช้ภายใน 24 ชม. → cron ลบ

### กันกดส่งซ้ำ (เน็ตมือถือหลุด)
`POST /runs` รับ header `Idempotency-Key` (UUID ที่หน้าเว็บสร้างตอนเปิดฟอร์ม) — ส่งซ้ำด้วยค่าเดิมได้ผลเดิม ไม่เกิดรายการซ้ำ

### ความปลอดภัย
| เรื่อง | วิธี |
|---|---|
| Session | คุกกี้ `httpOnly`, `Secure`, `SameSite=Lax` (JavaScript อ่านไม่ได้) |
| CSRF | คำขอที่เปลี่ยนข้อมูลต้องมี header `X-Requested-With: workingrun` |
| เดารหัสผ่าน | Turnstile + rate limit 10 ครั้ง/นาที/IP + ล็อกบัญชี 15 นาทีหลังผิด 5 ครั้ง |
| ล็อกอินผิด | ตอบ `INVALID_CREDENTIALS` เหมือนกันทั้งกรณีไม่มีผู้ใช้และรหัสผิด (ไม่บอกว่ารหัสพนักงานไหนมีอยู่) |
| รหัสผ่านชั่วคราว | แสดงครั้งเดียวตอนสร้าง/รีเซ็ต ระบบไม่เก็บแบบอ่านได้ |
| สิทธิ์ service_role | ใช้เฉพาะ server: สร้างผู้ใช้, รีเซ็ตรหัสผ่าน, cron — ไม่เคยส่งไปเบราว์เซอร์ |

### งานอัตโนมัติ (Cloudflare Cron Triggers — ไม่ใช่ HTTP endpoint)
| เวลา (ไทย) | งาน |

| ทุกวัน 03:30 | ลบบันทึกตรวจสอบเกิน 2 ปี + ประวัติล็อกอินเกิน 30 วัน |

## รหัส error → HTTP status

| HTTP | รหัส |
|---|---|
| 400 | `VALIDATION_ERROR`, `TURNSTILE_FAILED` |
| 401 | `NOT_AUTHENTICATED`, `INVALID_CREDENTIALS` |
| 403 | `FORBIDDEN`, `PASSWORD_CHANGE_REQUIRED`, `CONSENT_REQUIRED` |
| 404 | `NOT_FOUND`, `RUN_NOT_FOUND`, `USER_NOT_FOUND` |
| 409 | `CONFLICT`, `SEASON_OVERLAP`, `ACTIVE_SEASON_EXISTS`, `DELETION_ALREADY_REQUESTED`, `PRIVACY_NOTICE_OUTDATED` |
| 410 | `EVIDENCE_PURGED` |
| 413 / 415 | `FILE_TOO_LARGE` / `UNSUPPORTED_FILE_TYPE` |
| 422 | รหัสกฎธุรกิจจากฐานข้อมูลทั้งหมด (`RUN_DATE_IN_FUTURE`, `RUN_DATE_TOO_OLD`, `DISTANCE_BELOW_MIN`, `SEASON_HAS_PENDING_RUNS`, `CANNOT_REVIEW_OWN_RUN`, …) |
| 423 | `ACCOUNT_LOCKED` |
| 429 | `RATE_LIMITED` |

รูปแบบเดียวกันทุกช่องทาง:
```json
{ "error": { "code": "RUN_DATE_TOO_OLD", "message": "บันทึกย้อนหลังได้ไม่เกิน 7 วัน", "details": { "max_days": 7 } } }
```
